**测试日期**: 待执行  
**测试人员**: 待指定  
**相关任务**: TASK-035

## 测试环境

- **浏览器**: Chrome/Edge/Brave (Chromium内核)
- **扩展模式**: 开发模式 (`pnpm dev` 加载)
- **测试页面**: 
  - 设置页面: `chrome-extension://<ID>/options.html`
  - GitHub 仓库: `https://github.com/facebook/react`

## 前置条件

1. 运行 `pnpm dev` 启动开发服务器
2. 在 Chrome 中加载 `build/chrome-mv3-dev` 目录
3. 记录扩展 ID: `chrome://extensions/`

## 测试用例

### TC-301: 拖拽视觉反馈

**步骤**:
1. 打开设置页面 `chrome-extension://<ID>/options.html`
2. 找到工具列表（9 个工具项）
3. 鼠标悬停在左侧拖拽手柄（⋮⋮ 图标）上
4. 点击并按住拖拽手柄，向下拖动工具项

**预期结果**:
- [ ] 拖拽手柄光标变为 `grab`（悬停时）
- [ ] 拖拽时光标变为 `grabbing`
- [ ] 被拖动的工具项显示半透明效果（opacity: 0.4）
- [ ] 目标位置工具项高亮显示（蓝色边框）
- [ ] 拖动过程平滑，无卡顿（animation: 150ms）

---

### TC-302: 拖拽排序功能

**步骤**:
1. 在设置页面中，将 "GitHub.dev" (工具 #1) 拖拽到列表末尾
2. 释放鼠标
3. 观察工具列表顺序变化
4. 刷新设置页面

**预期结果**:
- [ ] 拖拽完成后，工具项立即移动到新位置
- [ ] 工具顺序变为: [2, 3, 4, 5, 6, 7, 8, 9, 1]
- [ ] 刷新页面后，工具顺序保持不变
- [ ] 无控制台错误

---

### TC-303: 拖拽顺序保存到 storage

**步骤**:
1. 在设置页面中拖拽工具（任意顺序调整）
2. 打开 DevTools → Application → Storage → Extension Storage
3. 查看 `chrome.storage.sync` 中的 `preferences` 键

**预期结果**:
- [ ] `toolOrder` 字段存在
- [ ] `toolOrder` 包含 9 个唯一 ID (1-9)
- [ ] `toolOrder` 顺序与设置页面一致
- [ ] 例如: `{"toolOrder": [2, 1, 3, 4, 5, 6, 7, 8, 9]}`

---

### TC-304: Content Script 菜单顺序同步

**步骤**:
1. 在设置页面中，将工具顺序调整为: [9, 8, 7, 6, 5, 4, 3, 2, 1]（完全倒序）
2. 打开 GitHub 仓库页面: `https://github.com/facebook/react`
3. 点击侧边栏按钮，打开工具菜单
4. 观察菜单中工具的顺序

**预期结果**:
- [ ] 菜单中工具顺序为: CodeWiki, DeepWiki, CodeSandbox, ...（倒序）
- [ ] 菜单顺序与设置页面一致
- [ ] 工具图标、名称、描述正确显示
- [ ] 无控制台错误

---

### TC-305: 实时更新（设置页面 → GitHub 页面）

**步骤**:
1. **同时打开两个标签页**:
   - 标签页 A: 设置页面 `chrome-extension://<ID>/options.html`
   - 标签页 B: GitHub 页面 `https://github.com/facebook/react`
2. 在标签页 B 中打开工具菜单（保持菜单打开状态）
3. 切换到标签页 A，拖拽工具顺序（如将第 1 个工具移到末尾）
4. 立即切换回标签页 B，观察菜单

**预期结果**:
- [ ] 标签页 B 的菜单**立即自动更新**（无需手动刷新）
- [ ] 菜单中工具顺序与设置页面一致
- [ ] 更新延迟 ≤500ms
- [ ] 无控制台错误

---

### TC-306: 拖拽到列表外部

**步骤**:
1. 在设置页面中，拖拽一个工具项
2. 尝试将其拖拽到工具列表容器外部（如页面顶部或底部）
3. 释放鼠标

**预期结果**:
- [ ] 拖拽被取消，工具项回到原位置
- [ ] SortableJS 自动处理边界限制
- [ ] 无控制台错误

---

### TC-307: 禁用工具的拖拽排序

**步骤**:
1. 在设置页面中，禁用某个工具（如 CodeWiki）
2. 拖拽其他工具，调整顺序
3. 重新启用 CodeWiki
4. 打开 GitHub 页面，查看菜单

**预期结果**:
- [ ] 禁用的工具仍保留在 `toolOrder` 中
- [ ] 拖拽其他工具时，禁用工具的相对位置保持不变
- [ ] 重新启用后，工具出现在原位置
- [ ] 菜单顺序正确

---

### TC-308: 新工具自动插入逻辑

**步骤**:
1. 在 DevTools → Application → Storage 中手动修改 `toolOrder`
2. 删除某个工具 ID（如 `[1, 2, 3, 4, 5, 6, 7, 8]`，缺少 9）
3. 刷新设置页面

**预期结果**:
- [ ] 设置页面自动回退到默认顺序 `[1, 2, 3, 4, 5, 6, 7, 8, 9]`
- [ ] 所有 9 个工具正常显示
- [ ] 控制台显示验证警告（可选）

---

### TC-309: 拖拽性能测试

**步骤**:
1. 在设置页面中，快速连续拖拽多个工具（如 10 次拖拽操作）
2. 观察拖拽响应延迟
3. 打开 DevTools → Performance 标签，录制拖拽操作

**预期结果**:
- [ ] 拖拽响应延迟 ≤50ms（P95）
- [ ] 动画流畅，无明显卡顿
- [ ] CPU 占用正常（≤30%）
- [ ] 无内存泄漏

---

### TC-310: 跨设备同步（chrome.storage.sync）

**步骤**:
1. 在设备 A（如电脑）上调整工具顺序
2. 等待 5-10 秒（chrome.storage.sync 同步延迟）
3. 在设备 B（如另一台电脑或笔记本）上打开设置页面

**预期结果**:
- [ ] 设备 B 的设置页面显示与设备 A 相同的工具顺序
- [ ] 同步延迟 ≤10 秒
- [ ] 无冲突或数据丢失
